# ADR-022: Dependency and Supply-Chain Security Policy

**Status:** Accepted

## Context

Modern JavaScript applications face severe supply-chain risks, including compromised packages, zero-day vulnerabilities (e.g. React2Shell CVE-2025-55182), and untrusted install scripts.

## Decision

Enforce a strict supply-chain and dependency governance policy:

1. Version Resolution: Package versions are resolved at install time, never typed from memory, and pinned strictly via pnpm-lock.yaml.
2. Supply-Chain Cooldown: pnpm minimumReleaseAge is configured to 1440 minutes (24 hours) to prevent automated installation of compromised zero-day releases.
3. Explicit Build Scripts: pnpm allowBuilds enforces an explicit allowlist. Transitive build scripts are denied by default.
4. Audit Gates: Automated CI runs pnpm audit --audit-level=high.
5. TypeScript Version: Pinned to 6.x until typed ESLint rules officially support TypeScript 7.x.

## Alternatives

- **Unpinned wildcard versions (^, ~):** Inconsistent builds between developers and sudden breakages when packages release updates.
- **Running pnpm approve-builds --all:** Disables crucial supply-chain protection and allows arbitrary native code execution during npm install.

## Consequences

- **Positive:** High supply-chain resilience, reproducible builds, and defense against malicious package injections.
- **Negative:** Requires manual review when upgrading dependencies or allowing native build scripts.
