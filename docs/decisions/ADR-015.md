# ADR-015: Document and Object Storage

**Status:** Accepted

## Context

Aureon processes large user documents (PDFs, Markdown, images, audio exports) that are inappropriate for storage directly in PostgreSQL relational columns.

## Decision

Adopt S3-compatible object storage via an abstract ObjectStoragePort. Local development uses MinIO running in Docker; production targets AWS S3 or Cloudflare R2.

- PostgreSQL stores metadata, mime-types, document chunk references, and object keys.
- Uploads and downloads use pre-signed URLs with short expiration windows.

## Alternatives

- **PostgreSQL BYTEA / Large Objects:** Bloats the relational database, degrades backup performance, and increases WAL volume.
- **Local filesystem storage:** Fails in containerized or multi-instance cloud deployments where local disks are ephemeral.

## Consequences

- **Positive:** Scalable, cost-effective storage for large binary files; relational database remains lean and fast.
- **Negative:** Requires managing object lifecycle policies and orphaned-file garbage collection.
