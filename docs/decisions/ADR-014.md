# ADR-014: Context Engine Subsystem

**Status:** Accepted

## Context

LLMs have finite context windows, non-linear pricing, and performance degradation ('lost in the middle') when overloaded with irrelevant context.

## Decision

Treat the Context Engine as a core, dedicated domain subsystem (modules/context):

- Dynamic Budget Allocation: Strict token budgeting across system instructions, user persona, retrieved knowledge chunks, task context, and recent conversation history.
- Priority Truncation: Hard deterministic priorities discard low-importance context first when budgets are tight.
- Audit Manifest: Every assembled context generates an inspection manifest recording which items were included, their token counts, and why certain chunks were discarded.
- Database Isolation: The Context Engine has no direct database access; it operates purely on data supplied by application services.

## Alternatives

- **Naive prompt concatenation:** Leads to context overflow, degraded reasoning quality, and unexpected token costs.
- **Provider-managed context caching only:** Useful for optimization, but does not solve token budget prioritization or multi-source context assembly.

## Consequences

- **Positive:** Transparent prompt composition, deterministic token costs, and high-fidelity LLM responses.
- **Negative:** Requires rigorous unit and evaluation test suites to maintain prompt balance.
