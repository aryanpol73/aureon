# ADR-020: AI Provider Configuration and Data Egress Controls

**Status:** Proposed, required before Phase 4

## Context

Sending user documents and personal notes to commercial AI APIs constitutes a severe privacy and regulatory boundary. Users must retain full control over data egress.

## Decision

Implement strict, per-workspace AI provider configuration and data egress controls:

- Workspace Consent: Hosted AI processing is disabled by default (hosted_ai_processing = false). Explicit user consent with policy version is required.
- Data Classification: Every AI call declares its egress data class (document_text, workspace_metadata, user_messages, memories). Calls lacking consent are blocked at the gateway.
- Zero Data Retention (ZDR): Production provider agreements must mandate Zero Data Retention and forbid training on customer data.
- Fallback: Without AI consent, full-text search and CRUD continue to function normally.

## Alternatives

- **Implicit data egress:** Violates privacy best practices and destroys user trust in personal operating system software.
- **Client-side direct API calls:** Exposes user API keys in browser environments and bypasses central budgeting.

## Consequences

- **Positive:** Industry-leading privacy posture, GDPR/compliance readiness, and user peace of mind.
- **Negative:** AI features remain locked until the user explicitly completes the consent flow.
