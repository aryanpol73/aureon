# ADR-002: Primary Language and Runtime (Node.js 24 LTS and Strict TypeScript)

**Status:** Accepted

## Context

The Aureon backend and frontend require high developer velocity, type-safe API contracts across the monorepo, robust asynchronous I/O primitives, and production-grade observability.

## Decision

Standardize on Node.js 24 LTS and strict TypeScript (ES2024 target, NodeNext module resolution). Package resolution uses source packages across the monorepo. Type checking enforces strict null checks, noUncheckedIndexedAccess, exactOptionalPropertyTypes, and isolatedModules. TypeScript compiler is pinned to 6.x per ADR-022 due to ecosystem tooling compatibility.

## Alternatives

- **Python (FastAPI):** Strong in AI libraries, but lacks unified contract sharing with Next.js, and multi-threading/async concurrency requires higher operational management.
- **Go/Rust:** High raw execution speed, but slower iteration velocity and duplication of domain models/DTOs between frontend and backend.
- **TypeScript 7.x:** Rejected temporarily because typescript-eslint typed linting does not yet support TS 7.

## Consequences

- **Positive:** Shared TypeScript interfaces across apps and packages, zero compilation step during local package development, native ESM loader support, and rich OpenTelemetry ecosystem.
- **Negative:** Node.js event loop requires care to prevent CPU-bound tasks from blocking I/O (mitigated by worker processes).
