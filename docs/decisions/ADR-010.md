# ADR-010: AI Gateway, Budget Ledger, and Kill Switch

**Status:** Accepted, amended

## Context

Uncontrolled AI model execution risks catastrophic financial runaway, provider rate-limit exhaustion, and lack of accountability for model usage across workspaces.

## Decision

Route all AI model interactions through a centralized AI Gateway with strict budget reservation, settlement, and kill-switch controls:

- Reserve -> Call -> Settle: Every AI request must atomically reserve budget across global, workspace-monthly, workspace-daily, and agent-run scopes using a fixed-order row lock in PostgreSQL.
- Fail-Closed: Calls are denied if budget limits are reached, if a model price is unknown, or if the kill switch is triggered.
- Kill Switch: Dual-layer kill switch: dynamic database-backed ai_controls table (10s TTL cache) and emergency environment variable AI_HARD_DISABLE=true.
- Dependency Boundary: Provider SDKs are strictly quarantined within packages/ai and cannot be imported by application modules.

## Alternatives

- **Post-hoc billing / usage logging:** Fails to prevent runaway costs from infinite agent loops or compromised keys.
- **Decentralized direct provider SDK calls in domain modules:** Violates single-responsibility, causes vendor lock-in, and makes observability impossible.

## Consequences

- **Positive:** Absolute protection against budget overrun, complete visibility into token consumption and costs, and immediate kill-switch capability.
- **Negative:** Adds a database reservation transaction before every AI model call (~1ms overhead).
