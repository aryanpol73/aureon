# ADR-019: Automated Testing Strategy

**Status:** Accepted

## Context

A production-grade system requires fast, reliable, and deterministic tests without relying on slow end-to-end browser tests for every verification.

## Decision

Adopt a Hexagonal Testing Pyramid:

1. Unit Tests: Test domain entities and application logic in isolation. Time-dependent code uses the Clock port (ManualClock) rather than system clocks or fake timers.
2. Integration Tests: Test repositories, RLS policies, and database transactions against real ephemeral PostgreSQL containers via @testcontainers/postgresql.
3. API Tests: Test HTTP routes using Fastify's inject() harness without binding network ports.
4. AI Evaluation: Golden-dataset regression tests measuring retrieval recall, context assembly accuracy, and tool-calling precision.

## Alternatives

- **Mocking database queries in memory:** Fails to test actual SQL syntax, complex joins, constraints, or Row-Level Security policies.
- **Manual QA:** Non-repeatable, slow, and incapable of catching subtle security regressions.

## Consequences

- **Positive:** Complete confidence in database constraints and RLS; zero test flakiness due to deterministic ManualClock; fast test execution.
- **Negative:** Ephemeral Docker containers require Docker to be running locally and in CI.
