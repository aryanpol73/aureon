# ADR-018: API Architecture and Real-Time Streaming

**Status:** Accepted

## Context

Client applications require low-latency REST endpoints for CRUD operations and real-time streaming for AI token generation and agent progress updates.

## Decision

Implement a Fastify HTTP API paired with Server-Sent Events (SSE) for streaming:

- Fastify: Chosen for low overhead, JSON schema validation, and modular plugin architecture.
- Server-Sent Events: Used for unidirectional token and agent step streaming. SSE connections pass through reverse proxies (Caddy) with flush_interval -1 to prevent buffer delays (verified in Spike S3).
- Strict Contracts: API route inputs and outputs are defined using shared TypeScript types in packages/contracts.

## Alternatives

- **WebSockets:** Bidirectional communication is unnecessary for agent streaming and adds stateful connection management and reconnection complexity.
- **Express.js:** Slower JSON serialization and lacks modern TypeScript ergonomics.

## Consequences

- **Positive:** Extremely fast HTTP throughput, simple standard HTTP streaming over standard port 443, and easy browser consumption via EventSource.
- **Negative:** Streaming connections require careful reverse proxy configuration to prevent proxy buffer accumulation.
