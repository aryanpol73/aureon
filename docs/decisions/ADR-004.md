# ADR-004: Primary Database (PostgreSQL 17 with pgvector)

**Status:** Accepted

## Context

Aureon requires relational consistency for identity, projects, and billing, robust JSONB support for dynamic schemas and audit events, native vector similarity search for knowledge retrieval, and row-level security for tenant isolation.

## Decision

Use PostgreSQL 17 with the official pgvector extension as the single unified operational datastore. Relational tables, full-text search tsvectors, HNSW vector embeddings, and background job queue tables all reside within the PostgreSQL cluster.

## Alternatives

- **Dedicated Vector DB (Pinecone, Qdrant, Milvus) + Relational DB:** Adds distributed transaction failure modes, two-phase commits, out-of-sync state during rollbacks, and operational burden.
- **NoSQL / Document Store (MongoDB):** Lacks ACID transactions across multiple entities and lacks native Row-Level Security.

## Consequences

- **Positive:** Atomic transactions spanning domain state, vector embeddings, and job queuing; zero data drift between relational data and embeddings; single backup and operational lifecycle.
- **Negative:** Demands careful index tuning (HNSW, GIN, B-tree) and connection pool sizing to prevent saturation.
