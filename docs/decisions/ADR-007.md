# ADR-007: Authentication and Session Management

**Status:** Accepted

## Context

Aureon v1 is a browser-first application for individual users with multi-tenant SaaS readiness. It requires secure, self-implemented authentication without external third-party identity dependencies while adhering to strict security standards.

## Decision

Implement server-side sessions with email/password authentication using standard vetted primitives:

- Password hashing: Argon2id (OWASP minimum m=19MiB, t=2, p=1).
- Session tokens: 256-bit CSPRNG tokens, stored as SHA-256 hashes on the server.
- Cookies: __Host-aureon_session; Secure; HttpOnly; SameSite=Lax; Path=/.
- Expiry & Rotation: 7-day idle / 30-day absolute; session rotated on login/privilege changes; token revocation writes audit events.
- Password reset: 256-bit single-use token, 30-minute expiry; revokes all existing sessions.
- Defense: Timing attack resistance via dummy hashes; IP and account rate-limiting; Origin header validation.

## Alternatives

- **JWT in localStorage:** Vulnerable to XSS token theft; cannot be revoked instantaneously.
- **Third-party Auth (Clerk, Auth0, Supabase Auth):** Introduces external vendor lock-in, recurring operational cost, and limits developer mastery of security foundations.

## Consequences

- **Positive:** Total ownership of security posture, zero third-party auth outages, instantaneous session revocation, and robust audit trail.
- **Negative:** Team carries the full security maintenance and testing burden (proven by exhaustive automated security test suites in M2.1).
