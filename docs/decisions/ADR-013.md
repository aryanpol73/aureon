# ADR-013: Distributed Tracing and Structured Logging

**Status:** Accepted with one item open

## Context

Diagnosing issues across HTTP requests, database transactions, background queue workers, and external AI calls requires correlated distributed tracing and structured logs.

## Decision

Adopt OpenTelemetry (OTel) for distributed tracing paired with Pino for structured JSON logging:

- Native ESM Instrumentation: Use Node.js native ESM loader hooks to auto-instrument HTTP and PostgreSQL clients.
- Trace Context Propagation: Fastify requests generate or extract W3C traceparent headers; pino loggers automatically attach current trace_id and span_id to all log records.
- Open Item: Verify @fastify/otel route spans on current package releases in M1.2.

## Alternatives

- **Winston / Morgan + Ad-hoc Loggers:** Lack native OpenTelemetry integration and produce unstructured or unstandardized logs.
- **Proprietary APM vendors (Datadog/NewRelic agent):** Incurs vendor lock-in; open-standard OpenTelemetry allows exporter flexibility.

## Consequences

- **Positive:** Unified end-to-end tracing across API, database, and workers; logs and traces share identical trace IDs (verified in Spike S3).
- **Negative:** ESM loader flags (--import) must be configured in Node runtime arguments.
