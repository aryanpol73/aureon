# ADR-021: Architecture Enforcement as Code

**Status:** Accepted

## Context

Architectural rules (clean architecture layers, tenant boundaries, dependency direction) degrade over time if enforced only through human code reviews.

## Decision

Enforce architectural constraints automatically via automated tooling and CI gates:

- Dependency Boundaries: dependency-cruiser validates layer hierarchy (domain -> kernel; application -> domain; infrastructure -> application) and bans circular dependencies.
- Database Isolation: apps/web is forbidden from importing database, ORM, or backend packages.
- AI SDK Quarantine: Provider SDKs may only be imported inside packages/ai.
- Clock Port: domain and application code are forbidden from using new Date(), Date.now(), Math.random(), or crypto.randomUUID().
- Fixture Validation: tools/arch-fixtures maintains deliberate violating files to ensure enforcement rules actually fail when broken.

## Alternatives

- **Code review guidelines only:** Inevitably fails as teams scale or developers rush to deliver features.
- **Microservices for physical separation:** Imposes massive operational cost solely to prevent import statements.

## Consequences

- **Positive:** Absolute automated guarantee of architectural integrity; regressions are caught instantly at commit and CI time.
- **Negative:** Setup and maintenance of lint and dependency-cruiser rule configurations.
