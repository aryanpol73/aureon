# ADR-011: Hybrid Knowledge Retrieval Architecture

**Status:** Accepted

## Context

Aureon users query complex documents, notes, tasks, and historical decisions. Pure keyword search misses semantic synonyms, while pure vector search misses exact keywords, code identifiers, and acronyms.

## Decision

Implement a Hybrid Retrieval pipeline combining:

1. Dense Vector Search: pgvector HNSW cosine similarity on chunk embeddings.
2. Sparse Lexical Search: PostgreSQL full-text search (tsvector and tsquery with English/custom dictionaries).
3. Reciprocal Rank Fusion (RRF): Combines ranks from vector and lexical passes with a k=60 smoothing factor.
4. Tenant Pre-filtering: Searches execute with strict WHERE workspace_id = $1 clauses prior to ranking.

## Alternatives

- **Dense vector search only:** Fails on exact code symbols, product SKUs, acronyms, and proper nouns.
- **External Elasticsearch / OpenSearch:** Increases operational complexity, adds infrastructure cost, and introduces data synchronization drift with PostgreSQL.

## Consequences

- **Positive:** State-of-the-art retrieval accuracy for technical and personal knowledge without external search infrastructure.
- **Negative:** Requires background indexing for both vector (HNSW) and text (GIN) indices, increasing storage footprint.
