## 2. Spike S1: pg-boss Queue

### Measurements

```text
RESULT s1.runtime_start {"ok":true}
RESULT s1.tx_semantics {"rollbackDiscards":true,"commitPersists":true}
RESULT s1.send_in_tx_ms {"p50":0.741,"p95":1.089,"n":500}
RESULT s1.crash_recovery {"heartbeatSeconds":30,"recoveryMs":60243}
RESULT s1.crash_recovery {"heartbeatSeconds":10,"recoveryMs":60227}
RESULT s1.dead_letter {"attempts":3,"msToDeadLetter":10085}
RESULT s1.runtime_create_queue {"allowed":true}
```

### Analysis & Findings

- **Transactional Semantics:** In-transaction enqueue (`boss.send(..., { db })`) completely joins caller transaction. Rollback discards job, commit persists job. Hot-path latency: `p50 = 0.74ms`, `p95 = 1.09ms`.
- **Crash Recovery:** Both 30s and 10s heartbeat settings recovered at ~60.2s. This proved crash recovery is dominated by the supervisor monitor interval (~60s) rather than heartbeat expiry duration.
- **Dead-Letter Queue:** Exact 3 retry attempts executed with exponential backoff. Dead-lettered job preserved original `sourceId`.
- **Schema Privileges (F6):** Runtime role `aureon_app` requires explicit `USAGE` on schema `pgboss`. Postgres default privileges on tables/sequences do not automatically grant usage on schemas created after initial role bootstrap.

## 3. Spike S1b: Worker Throughput & Latency

### Measurements

| Configuration                   | Idle Pickup (p50 / p95) | Drain Throughput (500 jobs) | Effective Rate     |
| ------------------------------- | ----------------------- | --------------------------- | ------------------ |
| `batchSize: 1, concurrency: 1`  | `2006 ms` / `2030 ms`   | 1000s estimated             | `0.50 jobs/s`      |
| `batchSize: 1, concurrency: 4`  | `2003 ms` / `2240 ms`   | 24.1s (50 jobs)             | `2.07 jobs/s`      |
| `batchSize: 10, concurrency: 1` | `2010 ms` / `2028 ms`   | 98.3s (500 jobs)            | `5.08 jobs/s`      |
| `batchSize: 10, concurrency: 4` | `2007 ms` / `2021 ms`   | 24.1s (500 jobs)            | **`20.73 jobs/s`** |

### Analysis

In `pg-boss` 12.x, burst mode (`burstWhenBatchFull`) is intentionally disabled when `batchSize = 1` to prevent polling loops. When `batchSize > 1`, burst mode engages and eliminates inter-poll delay, delivering **20.73 jobs/sec** at concurrency 4. Bulk queues (ingestion, embeddings) will configure `batchSize: 10, concurrency: 4`, while low-volume queues (daily plan) configure `concurrency: 1`.

## 4. Spike S2: Drizzle ORM, RLS & Tenancy Harness

### Measurements

- **Drizzle Drift Check:** 3 tables generated (`0000_init.sql`), custom RLS migration applied (`0001_rls.sql`), re-run reported `No schema changes, nothing to migrate`. Zero drift.
- **Tenancy Tests:** 7 of 7 passed:
  1. `app role is neither superuser nor BYPASSRLS` (24ms)
  2. `no tenant context: zero rows, no error (fail closed)` (3ms)
  3. `tenant A sees only A` (10ms)
  4. `WITH CHECK rejects writing into B under A context` (14ms, SQLSTATE `42501`)
  5. `composite FK rejects cross-workspace reference even when RLS is bypassed` (4ms, SQLSTATE `23503`)
  6. `tenant context does not leak to the next use of a pooled connection` (22ms)
  7. `RLS query plan & withTenant overhead` (1373ms)
- **RLS Query Plan & Overhead:**
  - Plan: Bitmap Index Scan on `tasks_workspace_created_idx`. Execution time: `2.03ms` across 50,000 tasks and 52 workspaces.
  - `withTenant` overhead vs baseline: `p50 = 0.88ms`, `p95 = 1.89ms` (under the 2.0ms budget).
  - Postgres template cloning: `p50 = 175ms` (viable for test-suite database isolation).
- **Planner Misestimate (F5):** `current_setting(...)` is opaque to the planner, resulting in a Bitmap Heap Scan + top-N sort. Application queries will explicitly supply `workspace_id = $1` in the query predicate (ADR-008 amendment).

## 5. Spike S3: Runtime, OpenTelemetry & Dev Experience

- **OpenTelemetry Correlation:** Native Node 24 ESM loader hooks correlated HTTP root span, Postgres connection span, Postgres query span, and Pino structured logs under identical `traceId: 5849e319686ddbe6f1285582529be597`.
- **Fastify Reload Time:** `tsx watch` reload time measured at **`519ms`** (< 2.0s threshold).
- **Next.js Monorepo Integration:** `@aureon/contracts` consumed as raw TypeScript source (`transpilePackages`). HMR picked up contract edits in **`226ms`**; production build static export succeeded.
- **SSE Streaming:** Reverse proxy through Caddy with `flush_interval -1` delivered events in real-time with ~255ms spacing without buffering.
